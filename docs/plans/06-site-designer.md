# 方案六：网站设计器（Site Designer）

状态：**待修订**（2026-10-16）。你选了**自由画布**（第 1 题）。开工前我会按自由画布重写本方案（尤其是手机上怎么显示），再请你批准其余问题。先做方案五第四批。

## 目标

让编辑部不用改代码，就能在后台自己调整读者网站的样子：首页怎么排、导航栏放什么、配色字体、页脚，以及新建自定义页面。

这项功能单独设一个 **Design（网站设计）** 权限，和 Issue 权限一样，由超级管理员单独授予。

## 一、先说做法：积木式，而不是自由画布

Canva 那样的自由画布，可以把东西拖到任意位置。我**不建议**读者网站这样做：

- **手机会乱。** 大部分同学用手机看。自由摆放的东西，在电脑上排好了，到手机上会重叠、错位或超出屏幕。
- **容易不像报纸。** 每一版都有人随手挪，几期之后网站就没有统一的风格了。纽约时报的版面看起来整齐，正是因为它用的是固定的网格。
- **无障碍会出问题。** 读屏软件按顺序朗读，自由摆放的内容顺序会乱。

所以我建议做成**"积木式"**的设计器：

- 首页由一块块**版块（积木）**从上到下拼成。
- 每块可以**拖动换顺序**，在右侧调设置：选哪几篇稿件、分几栏、有没有图片、标题多大。
- 每块在电脑和手机上都会自动排好，不用分别设计。
- 编辑时，右边**实时预览**整个首页，可以切换电脑和手机视图。

这和现在后台编辑稿件时的实时预览是同一套东西，用起来很顺手。

## 二、可以用的积木

| 积木                         | 作用                               | 可以调的设置                                          |
| ---------------------------- | ---------------------------------- | ----------------------------------------------------- |
| **头条（Lead）**             | 最大的那篇稿件                     | 选哪篇；大图在左/右/上；是否显示摘要                  |
| **稿件网格（Story grid）**   | 几篇稿件排成一行或几行             | 选稿件，或"自动：某栏目最新 N 篇"；2/3/4 栏；有无图片 |
| **栏目条（Section strip）**  | 一个栏目的最新稿件，带栏目标题     | 选栏目；显示几篇                                      |
| **专题（Topic spotlight）**  | 某个标签的稿件，配专题标题和简介   | 选标签；显示几篇                                      |
| **最新 + 最热（Rail）**      | 侧栏的 Latest 和 Most read         | 放左边还是右边；显示几条                              |
| **大图（Photo feature）**    | 一张大照片配标题，链接到稿件或专题 | 图片、标题、链接                                      |
| **文字块（Text）**           | 一段说明或通知，比如招新           | 正文、背景色（限定几种）                              |
| **期刊封面（Latest issue）** | 最新一期纸质版的封面和下载链接     | 显示/不显示                                           |
| **比赛与活动**               | 第四批做好后加：比分、本周活动     | 显示几条                                              |
| **分隔线（Divider）**        | 版块之间的粗线或细线               | 粗细                                                  |

以后需要新积木，再往里加。

**预设版式**：内置几个现成的首页，一键套用后再细调：

- **经典（Classic）**：像现在的首页；
- **大图（Photo-led）**：适合有好照片的一期；
- **突发（Breaking）**：一篇头条占满宽度，其他缩小。

## 三、其他可以自定义的

| 内容                 | 能调什么                                                       | 限制                                                                         |
| -------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **导航栏**           | 栏目的顺序、隐藏某个栏目、加自定义链接（如 Topics、Our Staff） | 最多 9 项，手机上会自动折叠                                                  |
| **配色**             | 强调色（链接、按钮）、头条横幅颜色                             | 只能从一组预先挑好的颜色里选，系统检查文字是否看得清（符合无障碍对比度标准） |
| **字体**             | 标题字体、正文字体                                             | 从 4–5 套搭配好的组合里选，不能随便上传字体                                  |
| **报头（Masthead）** | 报名的字体样式、下面的一行小字                                 | 报名本身在 Site Settings 里改                                                |
| **页脚**             | 链接、说明文字                                                 |                                                                              |
| **自定义页面**       | 新建页面，如"About us""Join us""Style guide"，用同样的积木拼   | 地址是 `/p/页面名`                                                           |

深色模式会自动适配所选的配色，不用另外设计。

## 四、权限

- 新增一项专项权限 **Design（网站设计）**。和 Issue 一样，可以授予 **Editor** 和 **Exec**，由超级管理员分配。超级管理员始终有这个权限。
- 有 Design 权限的人可以：编辑首页布局、导航栏、配色字体、页脚、自定义页面。
- **现有的 Front Page 权限怎么办**（见"需要你决定"第 2 条）：我建议**合并**。首页用积木排了以后，"选头条"本身就是首页布局的一部分，不好拆成两个权限。原来有 Front Page 权限的人自动改为 Design 权限。
- 没有 Design 权限的人能看到设计器，但只能看，不能改。

## 五、怎么上线

和栏目、头版现在的规则一致：

1. 在设计器里改动后，存为**草稿**。草稿可以先预览。
2. **默认跟下一期一起上线。** 发布期刊时，检查清单里会列出"网站设计有改动"，发布人确认后一起发布。
3. **急着换的话**：有 Issue 权限的人可以点 **"Publish design now"**，单独发布设计，占用本月 400 次部署里的 1 次。必须写原因，写入操作记录。（和横幅不同：网站布局是做在网页里的，所以必须重新部署。）
4. 每次发布的设计都保留历史版本（最近 10 个），可以**一键恢复**到以前的样子。恢复后同样要等下一期，或者"立即发布"。

## 六、防止出错

- **预览里能看到的，就是上线后的样子。** 预览用的就是读者网站的代码。
- 首页至少要有一个头条或稿件网格，否则不能保存。
- 积木选了"某篇稿件"但那篇被撤稿了：网站上这个位置会自动用最新的稿件补上，不会出现空白。
- 配色不够清楚（文字和背景对比度太低）会直接拒绝保存，并说明原因。
- 所有改动记录在操作记录里：谁、什么时间、改了什么。

## 七、对现有内容的影响

- 第一次上线时，现在的首页会被自动转换成"经典"版式。网站外观**完全不变**，直到有人去改。
- 后台的 **Front Page** 页面会被**设计器**取代。
- 不需要任何新的外部服务，也不增加费用。
- 工作量：比方案五任何一批都大，大约相当于第二批加第三批。建议分两步做：
  - **第一步**：首页积木、预设版式、导航栏、Design 权限、发布流程。
  - **第二步**：配色字体、页脚、自定义页面。

## 八、需要你做的（批准后）

- 不需要配置任何东西。
- 上线后，由超级管理员在 People 里给负责设计的同学勾上 **Design** 权限。

## 需要你决定

1. **做法**：同意做"积木式"设计器（推荐），还是一定要 Canva 那样的自由画布？
2. **Front Page 权限**：和新的 Design 权限合并（推荐），还是两个分开？
   - 分开：Front Page 管"首页放哪些稿件"，Design 管"网站长什么样"。
3. **上线方式**：同意"默认跟下一期，有 Issue 权限的人可以立即发布并占 1 次部署"吗？
4. **范围**：第三节里有没有不需要的，或者想加的？
5. **顺序**：先做这个，还是先做方案五的第四批（比分、日历、实时报道）？
