# 方案四：按期发布与静态网站

状态：**已批准并实现**（2026-10-14）。第七节两项例外按建议执行；另外加了发布前逐篇签字（见第十节）。

## 目标

1. 读者网站改为放在 **Cloudflare Pages** 上的静态页面：访问量不限，免费，地址短（如 `bosstoday.pages.dev`）。
2. 网站内容**只在发布期刊（Issue）时整体更新**，平时所有改动都先存为草稿。
3. 只有拥有 **Issue 权限**的人才能发布期刊。
4. 数据库记录每次部署，**每月满 400 次就拦截**，留出余量，避免触到 Cloudflare 免费版每月 500 次的上限。

## 一、整体架构

| 部分                                           | 放在哪                       | 谁会访问   |
| ---------------------------------------------- | ---------------------------- | ---------- |
| 读者网站：头版、文章、栏目、作者页、期刊、搜索 | Cloudflare Pages（静态页面） | 所有读者   |
| 后台、接口、实时预览、生成 PDF                 | Vercel（保持现状）           | 只有编辑部 |
| 图片                                           | GitHub Pages（已做好）       | 所有读者   |

- Vercel 上原来的读者页面地址，会自动跳转到 Cloudflare 上的对应页面，避免读者流量继续消耗 Vercel 的额度。
- 纸质版 PDF 改为在**发布期刊时生成一次**并存到图片仓库，读者直接下载现成的文件，不再每次访问都临时生成。
- 搜索改为在浏览器里进行：每次部署时预先生成一份文章索引。

## 二、新的稿件流程

```
草稿 → 待审 → 退回修改
         ↓
      待发布（Waiting Publish）—— 发布期刊时 ——→ 已发布
                                                   ↓
                                                 已撤稿
```

- 编辑审核通过后，稿件进入**待发布**，不会马上出现在网站上。原来的"Publish"按钮改为 **"Approve for next issue"**（批准进入下一期）。
- 待发布的稿件仍然可以被编辑修改，以发布期刊那一刻的内容为准。
- 编辑可以把待发布的稿件撤回草稿。

## 三、栏目、头版、站点设置也走草稿

- **栏目**（新增、改名、删除）、**头版编排**、**站点设置**（报名、About 页等）的改动，都先保存为草稿。
- 后台会标出"有未发布的改动"。
- 发布期刊时，这些改动和稿件一起上线。

## 四、发布期刊（Issue）

拥有 Issue 权限的人在期刊页面点 **"Publish issue"** 后，系统依次：

1. 列出这次将上线的全部内容，请发布人确认：
   - 所有待发布的稿件；
   - 栏目、头版、站点设置的未发布改动；
   - 本期纸质版（如果勾选了）。
2. 把以上内容全部改为"已发布"。
3. 如果有纸质版，生成 PDF 并存档。
4. 通知 Cloudflare 重新生成网站，并在数据库里记录这次部署。
5. 一两分钟后，网站更新完成。

**期刊和稿件的关系**：

- 期刊里的稿件列表会**自动填入所有待发布稿件**，可以手动删减和排序。
- 这个列表只决定纸质版收录哪些稿件、以什么顺序排版。
- 网站上会上线**全部**待发布稿件，不论是否被选进纸质版。

## 五、Issue 权限

- 新增一项专项权限 **Issue（发布期刊）**。
- 与其他专项不同，它可以授予 **Editor**，也可以授予 Exec，由超级管理员分配。
- 原来的"纸质版"专项保留，负责排版（选稿、栏宽、纸张大小），但**不能发布**。
- 超级管理员始终可以发布。

## 六、部署次数限制

- 数据库新建一张"部署记录"，每次触发部署都记一条：时间、操作人、原因、结果。
- 后台仪表盘显示：**本月已部署 N / 400 次**。
- **本月满 400 次后，发布期刊会被拦截**，提示等到下个月 1 日。
- 预留的 100 次只用于**紧急撤稿**（见第七节），撤稿最多用到 490 次为止。
- 计数按日历月统计（多伦多时间），每月 1 日归零。

## 七、两种例外（建议，需要你确认）

### 紧急撤稿：建议立即生效，不等下一期

如果误发了侵犯隐私、有事实错误或可能违反学校政策的内容，必须马上从网站撤下。

- 只有超级管理员和**标准与伦理编辑**（或拥有 Issue 权限的人）能撤稿。
- 撤稿会立刻触发一次部署，使用第六节预留的额度。
- 每次撤稿都必须填写原因，并写入操作记录。

### 突发新闻：建议用"网络版期刊"

两期之间发生重要新闻时，可以建一个**只有网络版、不出纸质版**的小期刊，里面只放这一篇或几篇，然后照常发布。这样不需要新的规则，也会正常计入部署次数。

## 八、对现有功能的影响

| 现在                             | 改为                                         |
| -------------------------------- | -------------------------------------------- |
| 编辑点 Publish，文章立刻上线     | 编辑点 Approve，文章进入待发布               |
| 头版、栏目、站点设置改完立即生效 | 先存草稿，发布期刊时生效                     |
| 纸质版 PDF 每次访问时生成        | 发布期刊时生成一次并存档                     |
| 搜索在服务器上进行               | 在浏览器里搜索预生成的索引                   |
| 读者网站在 Vercel                | 读者网站在 Cloudflare Pages，Vercel 只放后台 |
| 实时预览                         | 不变，仍在 Vercel 后台里                     |

## 九、需要你做的（批准后）

1. 注册 Cloudflare 账号，新建一个 Pages 项目，连接 GitHub 上的 `BOSS-Today` 仓库。构建命令等设置我会写进仓库，照着填即可。
2. 在 Pages 项目里创建一个 **Deploy Hook**（部署钩子），会得到一个网址。把它填进 Vercel 的环境变量 `CLOUDFLARE_DEPLOY_HOOK_URL`。这个网址相当于密钥，不要公开。
3. 把 Pages 项目的地址填进 Vercel 的 `PUBLIC_SITE_URL`。

## 需要你决定

1. **紧急撤稿**是否立即生效（第七节）？谁有权撤稿？
2. **突发新闻**是否用"网络版期刊"的方式处理？
3. 发布期刊时，网站是上线**全部**待发布稿件（按你的描述），还是只上线被选进这一期的稿件？
4. Issue 权限是否按第五节设计：可以授予 Editor 和 Exec，与"纸质版"专项分开？

## 十、发布前逐篇签字（2026-10-14 追加）

- 发布人必须先点开每一篇待发布稿件，才能勾选"已检查"。
- 每次勾选都立即记录到服务器：谁、哪个版本、什么时间（服务器时间）。勾选之后稿件又被修改的，必须重新检查。
- 有问题的稿件可以填写意见**打回**，它不会进入这一期。打回同样会被记录。
- 全部勾选后，发布人必须同意声明："I have read every story in this issue in full and checked it for accuracy, fairness, privacy and school policy. I am responsible for publishing it."
- 声明、发布人和时间永久保存在 **Issue sign-offs** 里，任何人（包括超级管理员）都不能修改或删除。
- 纸质版 PDF 没有在发布时存档，而是由 Vercel 在第一次请求时生成并缓存一小时，效果相同，实现更简单。
