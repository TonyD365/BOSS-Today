# 方案二：管理员后台

状态：**已批准，十项全部实现**（2026-10-14）。

后台地址是 `/admin`，基于 Payload CMS，界面为英文。

## 已经做好

- **Google 登录**：只有后台"Staff"名单里的邮箱能登录，名单外的人会被拒绝，也不会被存进数据库。
- **稿件**：标题、摘要、题图、正文、栏目、作者、草稿与发布、版本历史（每篇保留 10 版）。
- **正文编辑器**：标题、加粗、引用、列表、链接、插图、YouTube 视频。
- **期刊**：选稿、拖拽排序、卷号期号、是否出纸质版、纸张大小（Letter / Tabloid / A4 / A3）。
- **纸质版**：按期刊自动排成多栏报纸版式，在浏览器里打印或另存为 PDF。未发布的期刊只有登录的工作人员能预览。
- **栏目**：名称、说明、导航顺序。

## 已实现的十项

### 1. 仪表盘

登录后的第一屏，按等级显示不同内容：

| 等级 | 看到什么 |
|---|---|
| 记者 | 我的草稿、被退回的稿件、已发布的稿件 |
| 编辑 | 待审稿件队列、最近发布 |
| 管理员 | 上面全部，加上本期期刊的进度 |

### 2. 审稿流程

把现在的"草稿 / 已发布"扩展成五个状态：

草稿 → 待审 → 退回修改 → 已发布 → 已撤稿

- 记者点"提交审核"，稿件进入编辑的待审队列。
- 编辑可以发布，或填写意见后退回。
- 每次状态变化记录操作人和时间。

### 3. 头版编排

现在是在每篇稿件里选"头条 / 头版 / 普通"。计划改成一个单独的"Front Page"页面，把稿件拖进头条位、头版位，所见即所得。

### 4. 发布前预览

写稿时旁边实时显示这篇文章在网站上的样子。

### 5. 纸质版增强

- 每篇稿件可单独设置在纸质版里占几栏、是否带图。
- 版面里加入固定元素：目录、编辑部名单、公告位。
- 服务器直接生成 PDF 文件供下载（现在是用浏览器的打印功能）。
- 你们小组的设计稿出来后，按设计稿重做版式（待设计稿）。

### 6. 图片存到 GitHub

你提到图片要用自己的 GitHub CDN。计划做法：

- 编辑在后台上传图片，体验和现在一样。
- 服务器自动把图片压缩成 WebP（每张约 100–300 KB），提交到一个专门的 GitHub 图片仓库。
- 网站通过 jsDelivr 或 GitHub Pages 的地址加载图片。

需要注意的限制：

- GitHub 建议单个仓库不超过 1 GB，按压缩后的大小约能放 4000 张图。可以按学年分仓库。
- GitHub Pages 每月流量软上限为 100 GB，校报够用。
- 需要一个有该仓库写权限的 GitHub 令牌，配置在 Vercel 环境变量里。
- 没有配置 GitHub 仓库时，自动改用 Vercel Blob。
- 使用 GitHub 存储时，Vercel 上单张图片上传不能超过 4.5 MB（Vercel 的请求大小限制）。

### 7. 人员管理

按方案一的等级和专项权限实现，包括"已停用"状态。

### 8. 站点设置

一个设置页，不改代码就能修改：报纸名称和副标题、About 页面、社交媒体链接、页脚文字。

### 9. 后台外观

把登录页和左上角的 Payload 标志换成 BOSS Today 的报头。

### 10. 操作记录

记录谁在什么时候发布、撤稿、删除了什么，只有超级管理员能看。

## 已定的选项

- 十项全部实现，按建议顺序完成。
- 图片仓库：代码已就绪，填上 `GITHUB_IMAGES_REPO` 和 `GITHUB_IMAGES_TOKEN` 即可切换，仓库需公开。
- 纸质版：按学校自己打印设计。如果送印刷厂，需要按印刷厂的尺寸和出血再调整。
