# 方案五：编辑部协作与网站新功能

状态：**已批准**（2026-10-14）。第六节的问题都按建议执行；投稿改为必须实名、邮箱必须真实（见 3.1）。

**第一批、第二批已完成并上线**（2026-10-14）。第四批（赛果赛程、校园日历、实时报道）和阅读排行于同日追加并批准。

你选了 13 项功能，后来又加了 4 项，分四批做。每批做完、测试通过、推送上线后再开始下一批。

| 批次   | 内容                                                                      | 主题                                    |
| ------ | ------------------------------------------------------------------------- | --------------------------------------- |
| 第一批 | 写作提示、更正记录、专题标签、头条横幅、RSS、深色模式、分享按钮与阅读时间 | 小功能，马上能用                        |
| 第二批 | 选题与分配板、稿件模板、稿件内批注                                        | 编辑部协作                              |
| 第三批 | 读者投稿与爆料箱、阅读数据（含阅读排行）、编辑部介绍页                    | 读者互动与数据                          |
| 第四批 | 赛果与赛程、校园日历、实时报道                                            | 随时更新的内容（存在 KV，不占部署次数） |

不变的原则：

- 文章、栏目、标签等正式内容，**仍然只在发布期刊时上线**。
- 例外是存放在 **Cloudflare KV** 里、随时更新的小内容：头条横幅（1.4）、阅读排行（3.2）和第四批的三项。它们由读者的浏览器在打开页面时读取，**不重新部署网站，不占部署次数**。
- 读者网站仍是静态页面，仍在 Cloudflare Pages 上。所有新功能都只用免费服务。
- 部署次数仍按方案四计算，每月满 400 次拦截。

## 第一批：小功能

### 1.1 写作提示（后台）

稿件编辑页右侧显示一个小面板，随写随更新：

- 字数、预计阅读时间（按每分钟 230 个英文单词计算）。
- 标题长度：超过 70 个字符时提示"标题可能太长"。
- 摘要长度：显示 `已用 / 240`。
- 提醒：没有封面图；图片缺少说明文字（alt）或摄影署名；没有选栏目或作者。

这些只是**提醒**，不阻止保存。真正阻止发布的仍然是方案四里已有的检查（标题、摘要、正文、栏目、作者）。

### 1.2 更正记录（后台 + 网站）

- 稿件新增一栏 **Corrections（更正）**，每条包括：日期、更正内容。
- 网站文章末尾显示："**Correction, Oct. 14, 2026:** An earlier version of this article misstated …"；文章顶部显示"Updated Oct. 14, 2026"。
- 期刊页和首页不会因为更正而重新排序。
- **谁能加**：Editor 及以上。记者看到错误，告诉编辑即可（第二批的批注功能做好后，可以直接在稿件里批注）。
- **何时上线**：已发布的稿件加了更正，按方案四的规则变成"有未发布的改动"，经编辑批准后，跟下一期一起上线。如果错误严重，等不到下一期，仍然用紧急撤稿。
- 更正一旦发布，**不能删除**，只能再追加一条新的更正。这是报纸的通行做法，防止悄悄改掉错误。

### 1.3 专题标签（后台 + 网站）

- 新增 **Tags（标签）**：名称、简介、可选的封面图。例如 "Homecoming 2026"、"Student Council Election"。
- 稿件可以选多个标签。
- 网站为每个标签生成一个专题页 `/tags/homecoming-2026`，按时间列出所有相关稿件；文章页底部显示它的标签，可以点进去。
- 标签和栏目一样走草稿，**发布期刊时上线**。
- 谁能建标签：Editor 及以上。记者只能从已有标签里选，免得出现很多重复或拼错的标签。

### 1.4 头条横幅（后台 + 网站）

后台新增 **Banner（头条横幅）** 设置：

- 文字（最多 140 字符）、可选链接、样式（普通 / 紧急红色）、**到期时间**。
- 显示在网站每一页的最上方。

**存放位置**（2026-10-14 修改）：横幅**不放在静态网页里**，而是存在 **Cloudflare KV**（Cloudflare 免费的小型数据存储）。读者打开网页时，浏览器再去读取横幅。所以发布、修改、撤下横幅都**不需要重新部署网站，不消耗每月的部署次数**，一分钟内生效。

**上线方式**：

1. **默认跟下一期一起上线**：保存后就像其他草稿一样，等发布期刊。
2. **立即发布**：拥有 Issue 权限的人（和超级管理员）可以点 **"Publish banner now"**，必须写一句原因，写入操作记录。只发布横幅，其他草稿和待发布稿件不会跟着上线。

**到期自动消失**：读者的浏览器到点后自己隐藏横幅。

提前撤下横幅：清空文字，保存，再点一次"立即发布"。

### 1.5 RSS 订阅（网站）

- 全站 RSS：`/feed.xml`，最近 30 篇。
- 每个栏目和每个标签各有一个 RSS。
- 页面底部放一个 RSS 链接。零成本，每次部署时自动生成。

### 1.6 深色模式（网站）

- 默认跟随手机或电脑的系统设置。
- 页面顶部加一个切换按钮（浅色 / 深色 / 跟随系统），选择记在读者自己的浏览器里。
- 纸质版 PDF 不受影响，始终是白底黑字。

### 1.7 分享按钮与阅读时间（网站）

- 文章标题下方显示"5 min read"。
- 文章页有分享按钮：手机上调用系统自带的分享菜单；电脑上提供"复制链接"、邮件、X、Facebook。
- 都只是普通链接，**不加载任何第三方脚本**，不追踪读者。

## 第二批：编辑部协作

### 2.1 选题与分配板（后台）

新增 **Assignments（选题）**：

| 字段       | 说明                             |
| ---------- | -------------------------------- |
| 题目、说明 | 要写什么、采访谁、角度           |
| 栏目       | 新闻、体育……                     |
| 负责记者   | 可以多人；也可以空着，等记者认领 |
| 负责编辑   | 谁来审                           |
| 截稿时间   |                                  |
| 目标期刊   | 可选，打算放进哪一期             |
| 关联稿件   | 记者开始写时自动创建并关联       |

**看板**（后台新页面 `Assignment board`）分四列：

| 待认领             | 写作中                     | 待审           | 待发布               |
| ------------------ | -------------------------- | -------------- | -------------------- |
| 没有负责记者的选题 | 已分配，稿件是草稿或被退回 | 稿件已提交审核 | 稿件已批准，等下一期 |

- 后三列的状态**自动跟随稿件**，不用手动拖动，免得看板和实际情况对不上。
- 稿件发布后，选题自动归档，不再显示在看板上。
- 已过截稿时间的卡片标**红色**，24 小时内到期的标**黄色**。
- 可以按栏目、按记者筛选；记者默认只看到分配给自己的和待认领的。
- 记者点 **"Claim"** 认领选题；点 **"Start writing"** 自动建一篇稿件，题目、栏目、作者都已填好。

**谁能做什么**：

- Editor 及以上：新建、分配、修改、删除选题。
- 记者：认领待认领的选题；只能看，不能改别人的选题。
- 仪表盘新增一张卡片："我的选题"，显示自己负责的选题和截稿时间。

提醒：系统**不发邮件**（没有邮件服务），只在后台显示。

### 2.2 稿件模板（后台）

- 新增 **Templates（模板）**：名称、说明、默认栏目、正文结构。
- 预置几个模板（英文，可以修改）：
  - **Game Recap**（体育赛况）：比分导语、关键时刻、球员引语、下一场比赛。
  - **Event Coverage**（活动报道）：时间地点、发生了什么、参与者引语、意义。
  - **Profile**（人物专访）：开头场景、背景、问答或叙述、结尾。
  - **Op-Ed**（评论）：论点、论据、反方观点、结论。
  - **Club Spotlight**（社团介绍）。
- 新建稿件时可以选一个模板（或空白稿件），正文自动填入带提示的小标题。
- 提示文字用报社的传统记号 **TK**（"to come"，待补），如 "TK: final score and one-sentence summary"。不用方括号，是因为引语里常用 `[sic]`、`[the principal]` 这类方括号，会误判。
- 写作提示（1.1）会提醒"正文里还有 TK"，**批准和发布检查也会拦住**，防止带着提示文字上线。
- 谁能管理模板：Editor 及以上。

### 2.3 稿件内批注（后台）

像 Google Docs 的评论：

- 在编辑器里**选中一段文字**，点"Comment"，写下意见。被批注的文字会有黄色底色。
- 右侧显示所有批注，每条可以**回复**，形成讨论。
- 处理完点 **"Resolve"**，批注收起（不删除，可以查看历史）。
- 批注写着谁、什么时间。

**规则**：

- 能看到和发批注的：稿件作者、Editor 及以上。
- 只有发起人、稿件作者和 Editor 及以上能 Resolve。
- 批注**永远不会出现在网站上**，也不会进入纸质版。
- 发布检查：**还有未解决的批注时，稿件不能被批准**（Approve）。这一条可以按你的意见去掉。
- 退回修改时，编辑可以只写批注，不用再写一大段总意见。

**做法**：批注单独保存，**不改动稿件正文**，黄色底色只是在编辑器里显示。这样批注不可能误入网站或纸质版。被批注的文字如果后来被改掉或删掉，批注会保留在右侧，标注"原文已修改"。

发布检查同样会拦住带有未解决批注的稿件（期刊发布页会标红）。

## 第三批：读者互动与数据

### 3.1 读者投稿与爆料箱（网站 + 后台）

网站新增页面 **"Contact the newsroom"**，一个表单，分三类：

| 类型                 | 用途               |
| -------------------- | ------------------ |
| Letter to the Editor | 读者来信，可能刊登 |
| News Tip             | 新闻线索           |
| Correction Request   | 指出报道中的错误   |

表单内容：类型、正文（必填）、**真实姓名（必填）**、**联系邮箱（必填，必须验证；个人邮箱或学校邮箱都可以）**、年级或身份（如 Grade 11 / Parent / Teacher）、关联文章（选填）、勾选"我同意编辑部按方针处理我的投稿"。

**实名与真实邮箱**（2026-10-14 追加，所有投稿都必须这样，不再接受匿名）：

- 投稿人自己填写联系邮箱。提交后，系统给这个邮箱发一封**确认邮件**，点里面的链接，投稿才进入编辑的审核队列。这样能确认邮箱真实存在、确实是本人的。
- 没在 48 小时内确认的投稿自动删除。
- **保护发件额度**（防止有人反复提交，把 Gmail 每天 500 封的额度用光）：
  - 先过 Cloudflare Turnstile 人机验证，机器脚本发不了。
  - 同一个邮箱：每小时最多收 1 封确认邮件，每天最多 3 封。还没确认的投稿再提交，不会再发新邮件，而是提示"请先去邮箱点确认链接"。
  - 同一个网络：每小时最多提交 5 次。网络地址只做成不可还原的代码，一天后自动清除。
  - **全站每天最多发 100 封**确认邮件，只用到额度的五分之一。到了上限，表单显示"今天的投稿名额已满，请明天再试"，而且第二天自动恢复。编辑部自己用这个 Gmail 发邮件不受影响。
  - 仪表盘显示今天已发多少封；接近上限时提醒编辑。
- 发邮件用编辑部**单独注册的一个 Gmail**（开启"应用专用密码"给系统用）。Gmail 每天最多发 500 封，投稿每天也就几封，完全够用，免费。
- 教育局的学生邮箱可能拦截外部来信。设置好后先用一个学校邮箱收一封测试邮件；如果收不到，表单上会注明"学校邮箱可能收不到确认邮件，请用个人邮箱"。
- 真实姓名系统无法自动核实，由编辑部在**刊登来信前**通过邮箱联系核实。核实后 Editor 在后台勾选"Identity confirmed"，没勾选的来信不能转成稿件。

**防垃圾信息**：

- 使用 **Cloudflare Turnstile**（免费的人机验证，大多数时候读者不用做任何操作）。
- 每个网络地址每小时最多提交 5 次。
- 正文限 3000 字符。

**技术上**：网站是静态的，表单提交到 Vercel 上的一个接口，接口先检查 Turnstile，再存进数据库。投稿不会触发部署，不消耗额度。

**后台审核**（按你的要求由 Editor 审核）：

- 新增 **Submissions（读者投稿）** 队列，Editor 及以上可见；记者看不到（投稿人的联系方式属于隐私）。
- 状态：新收到 → 处理中 → 已采用 / 已回复 / 不采用 / 垃圾信息。
- 每条可以写内部备注、指定负责编辑。
- **来信转稿件**：一键把读者来信转成一篇"Letters"栏目的稿件草稿，照常走审核和发布流程。
- **线索转选题**：一键把线索转成一个选题（第二批的选题板）。
- **更正请求**：可以直接跳到对应稿件去加更正。
- 仪表盘新增卡片："N 条未处理的读者投稿"。

**隐私**：

- 网络地址只用于限流，**不保存**。
- 投稿处理完 **180 天后自动删除**联系方式（正文保留，用于存档）；标为垃圾信息的 30 天后整条删除。
- 表单页面写明：投稿必须实名，可能被刊登和编辑；编辑部可能通过邮箱联系核实身份。请和指导老师确认措辞。

### 3.2 阅读数据（网站 + 后台）

- 在 Cloudflare Pages 上开启 **Web Analytics**：免费、不用 Cookie、不收集个人信息、不需要弹出同意提示。
- 后台仪表盘新增 **"Readership"** 卡片：
  - 过去 7 天 / 30 天的总浏览量和访客数；
  - 浏览量最高的 10 篇文章；
  - 每个栏目的浏览量；
  - 读者从哪里来（直接访问、搜索引擎、社交媒体）。
- 每篇稿件的编辑页显示它的累计浏览量。
- 数据每小时从 Cloudflare 读取一次并缓存，打开仪表盘不会很慢。
- 谁能看：Editor 及以上。记者只能看到自己稿件的浏览量。
- **限制**：Cloudflare 免费版的数据只保留大约 6 个月。我会每天把每篇文章的浏览量存一份到我们自己的数据库，这样可以看全年的数据。
- **阅读排行（Most read）**：系统每小时算出过去 7 天浏览量最高的 10 篇，写进 KV，首页显示"Most read this week"。不占部署次数。
- 需要你做：在 Cloudflare 开启 Web Analytics，并给现有的 API Token 加上 "Analytics: Read" 权限。

### 3.3 编辑部介绍页（网站）

- 网站新增 **"Our Staff"** 页面，按方案三的职位分组：编辑部领导、版块编辑、记者、编校、视觉、版面。
- 每人显示：头像、姓名、职位、简介，点击进入他的作者页（已有）。
- 页面底部放 **"Join us"**：招新说明和投稿箱链接。
- 内容来自人员资料，**跟下一期一起更新**。
- **隐私**：每个人可以在自己的资料里选择"不在介绍页显示"。默认显示全名，你也可以决定改成"名 + 姓氏首字母"（如 Tony D.）。
- **依赖方案三**：职位分组要等方案三批准。如果方案三还没定，先按现有的 Title 文字显示，不分组。

## 第四批：随时更新的内容（存在 KV）

这三项和头条横幅一样存在 Cloudflare KV 里。后台一保存，读者一分钟内就能看到，**不重新部署网站，不占部署次数**。首页需要的所有 KV 内容会合并成一份，读者每打开一次首页只读一次 KV，免费额度（每天 10 万次读取）绰绰有余。万一读取失败，只是这几个小板块不显示，网站其他部分照常。

### 4.1 赛果与赛程

- 新增 **Games（比赛）**：项目和校队（如 Senior Boys Basketball）、对手、时间、地点、主场/客场、状态（未开始 / 进行中 / 已结束 / 取消）、双方比分、可选的赛况稿件链接。
- 首页显示一个小板块：最近的比分和接下来的几场比赛。网站另有一个完整的 **Scores & Schedule** 页面，可按项目筛选。
- 进行中的比赛显示"LIVE"，读者页面每分钟自动刷新比分。
- 谁能录入：记者及以上可以新建和更新比分；Editor 及以上可以删除。每次改动写入操作记录。

### 4.2 校园日历

- 新增 **Events（活动）**：名称、开始和结束时间、地点、简介、可选链接（如报名表或相关报道）。
- 首页显示 **"This week at Bur Oak"**：接下来 7 天的活动。网站另有完整的 **Calendar** 页面，按月显示。
- 已经过去的活动自动从首页消失。
- 谁能录入：Editor 及以上（避免出现错误的时间地点）。

### 4.3 实时报道

用于学生会选举开票、运动会、毕业典礼等当天持续更新的事件：

- 新增 **Live coverage（实时报道）**：标题、简介、状态（进行中 / 已结束），以及一条条带时间的短更新。每条更新可以附一张图片。
- 网站有对应的实时页面，最新的更新在最上面，读者页面每 30 秒自动刷新。进行中时，首页顶部显示"LIVE"入口。
- 结束后页面保留，作为记录。编辑也可以事后把内容整理成一篇正式稿件，照常走审核和发布流程。
- **谁能发更新：只有拥有 Issue 权限的人和超级管理员。** 实时更新绕过了"发布前逐篇签字"，所以只交给本来就对发布负责的人。每条更新都记录发布人和时间，可以修改或删除，修改和删除也写入操作记录。如果你想让现场的记者也能直接发，可以改成"记者写、有 Issue 权限的人点通过"，但会慢一些。

## 对现有内容的影响

- 现有稿件、栏目、期刊都不受影响，新字段默认为空。
- 数据库会新增几张表（标签、选题、模板、批注、投稿、阅读数据），每批上线时自动迁移。

- Neon 数据库：批注和投稿都是纯文字，三批全部加起来预计不到 50 MB，远低于免费额度。

## 需要你做的（批准后）

- 第一批、第二批：不需要。
- 第三批：
  1. 在 Cloudflare 新建一个 **Turnstile** 站点，把两个密钥分别填进 Vercel（`TURNSTILE_SECRET_KEY`）和 Cloudflare Pages（`TURNSTILE_SITE_KEY`）。我会写清楚步骤。
  2. 开启 **Web Analytics**，给 API Token 加 "Analytics: Read" 权限。
  3. 注册一个编辑部专用的 Gmail，开启两步验证后生成"应用专用密码"，填进 Vercel（`SMTP_USER`、`SMTP_PASSWORD`），用于发投稿确认邮件。
  4. 和指导老师确认投稿须知的措辞。

## 需要你决定

1. **分批顺序**是否同意？要不要把某一项提前（比如把批注放进第一批）？
2. **更正**（1.2）：是否同意"发布后不能删除，只能追加"？
3. **头条横幅**（1.4）："立即发布"是否只发横幅、不带其他内容？
4. **批注**（2.3）：有未解决的批注时，是否禁止批准稿件？
5. **投稿**（3.1）：已定为全部实名，联系邮箱自己填写（个人或学校邮箱都可以）。邮箱用确认邮件验证（编辑部专用 Gmail 发送）；来信刊登前编辑仍会核实身份。联系方式 180 天后删除。
6. **介绍页**（3.3）：显示全名，还是"名 + 姓氏首字母"？
